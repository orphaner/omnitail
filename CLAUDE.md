# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

`mtr` is a modern Rust clone of `multitail`: one TUI showing several log streams at once in stacked panes. Unlike multitail it is built around pluggable *sources*: files, arbitrary commands, docker, and later kubernetes and other streams. `specs.md` holds the user's goals. The multitail C sources at `/Users/nicolas/geekmac/multitail` are the reference for behavior and key bindings (for example `mt.c` for the key dispatch). The user writes in French.

## Commands

```bash
cargo build
cargo test                    # all tests; a single one: cargo test <name filter>, e.g. cargo test rotation
cargo clippy --all-targets    # expected to be warning-free
cargo run -- _geek/small.txt 'cmd:ping -i 0.5 127.0.0.1' docker:<container>
```

The app needs a real TTY. mtr's own logs go to a file (`--log-file`, `$TMPDIR/mtr.log` by default, level set by `MTR_LOG`), never to stdout or stderr. Sample inputs are in `_geek/`.

To check the real binary without an interactive terminal, run it inside `script` with an explicit size and keys piped in, then replay the capture with a terminal emulator such as Python `pyte`:
`(sleep 1; printf b; sleep .3; printf q) | script -q out.tty sh -c 'stty rows 30 cols 100; exec ./target/debug/mtr …'`.
Without `stty`, the pty is 0×0 and nothing is drawn.

## Architecture

The data flows one way: **sources → bounded mpsc channel → `App` state → `ui` draws it**.

- `spec.rs`: `SourceSpec` (file, cmd, docker, compose, k8s, journal, stdin), parsed from `type:arg` CLI arguments (a bare argument is a file, `-` is stdin). Short prefixes (`d:`, `dc:`) exist on the CLI only, because they are quick to type. Config files keep the explicit `type` names on purpose (the user's choice). `SourceConfig` is a `SourceSpec` (flattened, tagged by `type`) plus options any source can have: `name`, `lines`, `restart` (defaults to on for docker, compose and k8s).
- `config.rs`: loads `-c file.toml` (`[[source]]` tables plus global options; relative paths resolve against the file) and merges it with the CLI into `Settings`. Config sources come first, and CLI options win.
- `source/`: the `Source` trait (`spawn(self: Box<Self>, Emitter) -> JoinHandle`), with each source running as its own tokio task and sending `SourceEvent::{Line, Reset, Status}`. `expand()` turns a source into several panes before startup (compose: one per service, listed with `docker compose config --services`). `build()` then maps each `SourceConfig` to an implementation. **This is where a new source type goes.**
  - `file.rs`: `FileFollower` is the synchronous core, with one `poll()` per wake-up. It handles the initial `-n` lines, truncation (size < position), in-place rewrites by editors (the last 256 bytes read no longer match what is on disk, even when the file grew), rotation (device and inode change: it drains the old file first) and a missing file (`Waiting` status). Truncation and rewrite emit `SourceEvent::Reset(reason)`, which the app turns into a `ClearMark`. `FileSource` wakes it through `notify` on the parent directory, plus a 1s polling fallback. Tests drive `FileFollower` directly.
  - `command.rs`: `CommandSource` runs an `Argv` closure that rebuilds the command line for each run, given when the previous run ended. Each run gets its own process group (killed with `killpg` on drop, so `a | b` and background jobs die too) and stdin set to null (the TUI owns the terminal). stdout and stderr are merged, and the exit status is reported. With `restart`, it starts again with a 1s to 30s backoff. The app counts restarts (↻n in the title) when it sees `Running` after `Exited` or `Error`.
  - `tools.rs`: the `Argv` builders for docker, compose, kubectl and journalctl. The first run uses `--tail N`, and restarts use `--since <end of previous run>` so the tail is not replayed. These are CLI-backed POCs; native clients (bollard, kube-rs) are planned behind the same trait. Note: `docker compose logs -f` keeps following through container restarts by itself, whereas `docker logs -f` exits.
  - `stdin.rs`: reads on a plain std thread, so that a blocked read cannot stop the runtime from shutting down. crossterm reads keys from `/dev/tty` when stdin is a pipe.
- `color/`: mtr's own coloring. `scheme.rs` holds `Rule`s (a regex, a group, a style) compiled into a `Scheme`, which uses a `RegexSet` prefilter and lets the first rule win on overlap. `Library` loads, in increasing priority, `multitail.toml` (62 schemes converted from multitail), `builtin.toml` (ours) and the user's `[scheme.<name>]` tables, all in the same format. A multitail scheme shadowed by one of ours stays reachable as `<name>-multitail`. Multitail schemes are compiled lazily on first use (`Slot`), because compiling 700 regexes at every start is too slow; ours and the user's are compiled eagerly so config errors show at start, and a test compiles every multitail one. `paths` regexes choose a file's scheme (`for_path`: higher origin wins, then the first declared, as in multitail). `--list-schemes` prints them all. **`multitail.toml` is generated by `scripts/convert-multitail.py`: change the script, not the file.** It skips value-comparison rules (`cs_re_val_*`), keeps the first of alternating colors, and excludes niche or dead software (`EXCLUDED`). multitail is MIT; its notice is in `THIRD_PARTY_LICENSES` and in the file header. `detect.rs` guesses `json`/`http`/`syslog`/`logfmt` from a source's first 20 lines. `PaneColor` holds a pane's state (`Choice::Auto|Named|Off`, enabled, label), and the app feeds it lines through `observe()`. `style.rs` maps style names to the fixed palette. Coloring happens at render time in `ui/text.rs::rows`. A line containing ESC keeps the source's own ANSI colors, unless `--strip-ansi` is set, in which case the scheme applies to the stripped text.
- `pattern.rs`: `Pattern`, a user-typed regex with smart case and an optional leading `!` (negation, only for filters). `accepts()` ignores the source's ANSI codes.
- `view.rs`: `HistoryView`, the single way to look at history for full-screen views. `Target::Pane(i)` uses a pane's sequence numbers as positions; `Target::Merged` is an index of `(pane, seq)` in arrival order (built by `B`, then appended to by `App::ingest` while open). The view applies the view filter and provides `next`/`resolve`/`search`/`count`, which both keys and rendering use.
- `buffer.rs`: one `VecDeque` history per source (each `Entry` has its text, global arrival rank and arrival time), with **stable sequence numbers** that survive eviction. Clearing a pane (`N`/`n`) only pushes a `ClearMark`, so panes show lines from `view_start()` on while the scrollback still shows everything, with marks drawn as separators. Views refer to lines by `Seq`, never by index.
- `app.rs`: `App` holds the state (`Mode::{Panes, Select, Scrollback, Detail}`, plus an optional `Prompt` overlay that takes all keys while open) and the key handling (`handle_key`, which dispatches to one method per mode and is unit-tested without a terminal). `submit()` applies what was typed according to `PromptKind`: search, view filter, pane filter or highlight. `run()` is the `tokio::select!` loop over crossterm's `EventStream`, source events and SIGTERM, SIGHUP and SIGINT. A signal quits cleanly, so that dropping the sources stops their processes. Events arrive in batches and the screen redraws only when something changed.
- `ui/`: drawing only. Its exception is that full-screen views write back what they showed for the next key press: the scrollback writes `top` and `page`, and the detail view writes `max_scroll` and `page`. The scrollback keeps a line `cursor` (`None` = on the last line and following). Layout moves the view as little as possible to keep the cursor visible (`top_anchored`/`bottom_anchored`). `detail.rs` shows one line, and `split_json` finds a JSON object or array running to the end of the line, even after a prefix; it is pretty-printed in key order (`serde_json` `preserve_order`) and colored with the `json` scheme. `layout.rs` has the `PaneLayout` trait (only `Stacked` exists today). `text.rs`: `Render` (width, strip, scheme, wrap, hscroll) turns a raw line into rows. ANSI is parsed with `ansi-to-tui`. With `wrap`, lines are word-wrapped (breaking inside a word only when it is wider than the screen); without it, they are cut with `‹`/`›` markers. UI tests render the full screen with ratatui's `TestBackend`. mtr's own chrome only uses the fixed 256-palette constants at the top of `ui/mod.rs`, never named colors (`Color::Blue`…), because terminal themes remap those. Log content keeps the terminal defaults and its own ANSI colors.

## Keys (multitail-compatible where possible)

`q`/`Esc` quit (or leave a popup or the scrollback), `Ctrl+C` quits from anywhere. `N` clears all panes, `n` opens a picker to clear one. `b` opens a picker, then shows the scrollback (`j`/`k`, `PgUp`/`PgDn`, `g`/`G`). `C`/`c` toggle coloring, `s` opens the scheme popup (`Mode::Schemes`, filtered by typed text over names and descriptions, so every scheme needs a searchable description; chosen schemes are chained with `generic`), and `P`/`p` toggle pause. A paused pane freezes at `Pane::paused` while the buffer keeps receiving. Convention: uppercase acts on all panes, lowercase opens the picker for one; this is the opposite of multitail's `p`/`P`, chosen for consistency with `N`/`n`. `h`/`F1` open the help overlay (`App::help`, rendered by `ui/help.rs`) from any view except the picker. It shows the current view's sections (`help::sections`), or every section after `Tab`. Its sections are static tables there: **update them when adding or changing a key.** `w` toggles wrapping. `E`/`e` set pane filters and `/` highlights in all panes. `B` opens the merged history. In history views, as in `less`: `/` `?` `n` `N` `&`. `t` shows arrival times, and `p` pauses the view (`Scrollback::paused` caps `HistoryView::end` through `until()`), independently of pane pauses. In the scrollback, `Enter` opens the detail view and `y` copies the line: `App::clipboard` is sent by the event loop through the system tool (`pbcopy`, `wl-copy`, `xclip`, `xsel`) when local, or OSC 52 over SSH or as a last resort. iTerm2 ignores OSC 52 by default, which is why local copies avoid it. With a single pane, the picker is skipped.

## Demo

`demo/` has a compose project (`mtrdemo`): `web` (plain), `db` (its own ANSI colors), `nginx` (access logs), `api` (JSON) and `worker` (logfmt). `demo/stack.toml` follows all of them, with a custom scheme on `web`, plus CoreDNS on the default kube context (OrbStack locally). Only read-only kube commands are run against that cluster.

## Roadmap context

Milestones done: 1 (core TUI), 2 (sources: config file, compose, k8s, journal, stdin, restart) and coloring (schemes, detection, c/C). Navigation (search, filters, highlight, `B`, `t`) is done too. Explicitly deferred: native docker and kubernetes, other layouts (first idea: shrink empty or waiting panes), formatters (pretty JSON, field selection), value-based colors (multitail's `cs_re_val_*`), mouse support.
